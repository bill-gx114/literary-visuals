# 文学意象转译

让读者把画面与这段文字放在一起时，既能找到具体联系，又能感受到文字未直说的部分。风格服务于这一次阅读，不预设抽象、复古、冷色、孤独人物或固定主体。精确的取舍、构图和材质比“高级感”标签更有用。

## 先选择，再生成

收到创作文本后读 [生成前选择](references/intake.md)，收集尚未明确的四项：**画面表达、交付形式、尺寸（附用途）、文字显示方式**。使用宿主可用的交互工具；无工具时用紧凑文字选项。已有答案沿用，只问缺项。修改 Skill 本身不触发作品问卷。

用户确认后才生成正式作品。等待期间可核对出处；预选、超时和未回复不是接受默认值。用户说“你决定/直接做”时可代选对应范围，简述配置后执行，不额外审批。长文的“由你决定风格”不等于“由你删节原文”。

把原文、原署名和实际答案存入 `request.json`；`delivery` 记录格式、尺寸、文字版本和视频时长。参阅 [制作与导出](references/production.md)。

## 理解文本，而后选择媒介

1. 搜索有辨识度的短语，读匹配段落的上下文。优先原作、出版社或可靠学术资料；未联网则明确未核实。记录作品、作者、章节、版本和页码各自的确定程度。两至三轮定向检索仍无可靠结果时依文本继续，不把未知来源称为原创。复杂情况读 [出处与语境](references/provenance.md)。
2. 引用作者或原著时，按 [出处与语境](references/provenance.md)主动检索作者相关背景、该作品的文学风格，以及写作时期和地域的视觉文化。分清作者时代、故事时代、后世改编；把可靠背景转成具体的视觉候选，不将时代流行等同于作者偏好。用户原创或来源不明时不虚构作者研究。
3. 读 [文本分型与文字处理](references/text-treatment.md)：长度决定阅读负担；意象、否定、关系和转折决定画什么。这是两个独立维度。不要让长文天然变成插画加正文，或让短句天然变成抽象壁纸。
4. 写出一句核心判断，以及一至三个来自原文的**语义锚点**：文字证据 → 可见的形态、空间或动作 → 传达的感受。至少一个锚点体现关系或变化，不能全是名词。短句只有一个充分锚点也可成立，不凑数。
5. 读 [艺术指导](references/art-direction.md)，内部比较二至三个在构图或表达机制上不同的方向，选一个制作。有可靠时代视觉资料时，将其纳入候选并说明采用或舍弃的理由；用户指定风格时在该风格内比较。说明选中理由，不把内部比较变成额外风格问卷，也不默认生成多份成品。

把判断存为作品目录的 `art-direction.json`，只需本次有用的字段：

```json
{
  "core": "近在院内的生命仍在继续，想靠近的人却已无法进入",
  "text_profile": {"length": "passage", "structure": "narrative-turn", "emotion": "亲近 → 阻隔 → 独处中的余温"},
  "anchors": [
    {"evidence": "过道窄到", "visible": "前景向内延伸的通路在转角收紧", "feeling": "可接近而不可抵达"},
    {"evidence": "年年都开花", "visible": "内侧有微弱生长的痕迹，视线却被遮住", "feeling": "生命延续与人的缺席并置"}
  ],
  "alternatives": ["空间错位的纸雕", "压缩透视的绘画", "遮挡与透光的摄影式构图"],
  "chosen": "空间错位的纸雕；以通路的断续承担阻隔，而非复古道具",
  "avoid": ["把合欢树完整展示成赏花风景", "以空巷独自承担全部悲伤"],
  "text_plan": "按用户确认的完整原文排版，先验算阅读空间",
  "motion": "静态；视线沿通路靠近后停住"
}
```

示例是分析颗粒度，不是固定审美或每次必填的主题。出处、作者及时代证据保存在 `research.md`；`art-direction.json` 记录这些证据实际影响了哪些选择，以及本次属于时代取材、后世传统借鉴还是当代转译。查证事实与艺术解释分开记录。

## 先把画文关系做成立

- 每件作品选择有辨识力的主体、空间关系或变化；形象可以显现，也可以通过缺席、痕迹、尺度反差被感知。抽象作品仍要有可见的语义锚点，具象作品也不逐项复述情节。
- “多变”指媒介、构图、视点、形态语言和运动机制能随文本改变。调色不算结构变化。若能看到最近作品，比较是否重复相同主体与构图；除非用户在做系列或文本确有依据，否则调整方向。不读取无关个人历史来凑对照。
- 文字位置与画面同时设计，留出真实的阅读空间。不要默认上半幅通用插画、下半幅全文；这种编辑式排版只有适合用户用途时才采用。完整原文、授权节选和纯画面按选择交付，不擅自删字。
- 运动来自文本的动作、停顿或转折；文字适合静止就保持静止。动态通常低频、局部、可暂停，支持减少动态效果。文本需要急促、冲突或喜悦时可改变节奏，不把一切做成缓慢哀伤。
- [作品案例](references/cases.md)按相近问题选读。历史案例演示一种解释，不能作为作者、国别或情绪的默认模板。

## 制作、检查、迭代

按已确认的成品选择工具。绘画、摄影感与复杂物象可用宿主图像生成工具；精确几何、材料动力或交互可用程序绘制；叙事视频需要分镜和时间结构。先检查工具能力与用户约束，不因随包有着色器就把所有内容导向 WebGL。

默认程序动态作品可使用离线底座，无 CDN、外链字体或聊天专用 API：

```bash
python3 scripts/build_artwork.py --spec path/to/artwork.json --shader path/to/original.glsl --output output/artwork.html
```

命令相对 Skill 根目录示意。先创作本次规格和着色器，勿只替换案例文本。带字图应使用确定性排版，避免用生成图中的字承担精确引用。完整制作能力、文字边界和真实导出见 [制作与导出](references/production.md)。

实际打开作品，按 [画文契合与视觉验收](references/visual-review.md)检查；发现主要关系缺失、气氛矛盾或可读性不足时，针对该问题修改并重看。通常一至两轮局部修正；若核心方向失败，允许重构一次。到第三轮仍不成立时如实说明未解决处与已有文件，不用“已验证高级感”代替判断，也不无限生成。

- PNG 提供实际图片，MP4 提供实际视频，HTML 提供可独立打开的文件；不默认附送所有格式。网页预览不是视频，录屏也不是视频模型生成。
- 双文字版本用相同构图和时刻/时间段导出 `-with-text` 与 `-art` 两份文件。无字版不含原句、作者或标题；出处保留在外部说明。
- 格式、比例、文字范围、时长必须与 `request.json` 一致。更换画幅重新构图；原文与署名单独检查。缺能力或打不开时保留源文件并说明限制。
- 不自动上传或公开作品。用户明确要求分享/托管时再处理。

最终展示成品与下载入口后，**固定附上面向用户的作品解析**，按 [成品解析](references/interpretation.md)说明文本核心、画面对应、风格与时代依据、文字和构图取舍，并标明来源状态。解析也保存为 `interpretation.md`；不能只给文件链接而省略回复中的解析。纯画面版本同样附外部解析，解释不印进画里。若用户明确要求只给成品，则遵从该要求。技术自检另存 `review.md`，解析不能替画面补造看不见的含义。
